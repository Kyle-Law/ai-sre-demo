Related open-source projects

Which existing projects overlap with this repo (read-only AI diagnosis → Jira → GitHub PR → human merge → ArgoCD → verify), what to borrow from each, and where this demo already goes further. Researched October 2026.

Most details come from project READMEs and docs, but some are from blogs and directory listings. Check licences, CRD names and flags against each project's own docs before you depend on them.

Where to start

1

Run HolmesGPT on the same scenarios

It's the closest existing agent. Comparing diagnoses on scenarios 01–06 is the most honest test of whether step 11's investigation adds anything.

2

Give the investigator Job read-only MCP servers

Use mcp-grafana --disable-write and kubernetes-mcp-server --read-only instead of hand-written clients. Step 09 RBAC stays the real backstop.

3

Read kagent's CRDs before growing step 12

It has already worked out how to declare an agent, its model and its tools as Kubernetes resources, the general version of AgentSession.

What this repo does that the others don't advertise

Typical AI SRE tool

  • Investigates and explains; may suggest a fix
  • Fixes, if any, are patched straight into the cluster (K8sGPT auto-remediation) or left to a human
  • The story ends at "here is the root cause"

This demo

  • Fix goes through git as a PR, a human merges it, and ArgoCD applies it
  • The agent follows the PR through review, merge, sync and verification, then closes the ticket
  • MTTR split into automated vs human time, and an auditable "how it found it" log
  • LLM runs in a Job with no write credentials, pinned in place by an admission policy

Projects

HolmesGPT

CNCF Sandbox · started at Robusta
Closest overlap
step 11step 12

What it is: an open-source agent that investigates incidents. It has read-only toolsets (Kubernetes, logs, Prometheus) declared in YAML, alert sources including Alertmanager, PagerDuty and Jira (with findings written back), an in-cluster operator mode with scheduled health checks, and a GitHub integration that can open fix PRs.

Borrow: the toolset-as-config pattern, and use it as a benchmark for your diagnoses. Its tool-calling loop isn't deterministic, and neither is yours: compare over several runs.

kagent

CNCF Sandbox · Solo.io
Closest to step 12
step 12

What it is: a framework for running AI agents on Kubernetes. Agent (prompt + tools + model ref), ModelConfig (provider, model, key Secret) and MCP tool servers are custom resources, run by a Go controller, with a UI and a CLI. It ships MCP tools for Kubernetes, Helm, Argo, Prometheus, Grafana and Cilium.

Borrow: separating the agent definition from per-incident state. It's a framework, not an SRE agent, so it would host your logic rather than replace it.

K8sGPT

CNCF
Contrast case
step 11demo story

What it is: 50+ rule-based Kubernetes checks with an LLM explanation, as a CLI or an operator. Its experimental auto-remediation records fixes as Mutation resources and patches the cluster directly. GitOps support is on its roadmap.

Borrow: run its checks before the LLM, so Haiku starts from known findings and uses fewer turns. In the demo, contrast direct patching with your PR-and-human-merge path.

kubernetes-mcp-server

containers/ · Red Hat
Replace hand-rolled tool
step 11

What it is: a Go MCP server that talks to the Kubernetes API directly. --read-only blocks all create, update and delete; --disable-destructive blocks only update and delete.

Watch out: it doesn't do what kube.py does: refuse Secret reads and block --as / --token. RBAC still has to stop Secret reads.

mcp-grafana

Grafana Labs
Replace hand-rolled tool
step 11

What it is: the official Grafana MCP server with 40+ tools (dashboards, PromQL, alert state, incidents). --disable-write switches off dashboard, folder, incident and alert-rule changes.

Borrow: replaces grafana.py; keep the Viewer-role token as the real limit.

argocd-mcp

Akuity · argoproj-labs
Optional
step 11step 12

What it is: an MCP server for Argo CD: Application status, sync state, resource tree and logs.

Watch out: it also has tools to sync, create and delete Applications. Allow only the read tools for the investigator; your controller's sync-revision check already works without it.

Keep

keephq
Replace step 08 bridge
step 08

What it is: an open-source alert management and AIOps platform. It collects alerts from 100+ sources, groups them into incidents with CEL rules or AI, and its YAML workflows can create and update Jira tickets.

Borrow: grouping and de-duplication well beyond the bridge's fingerprint matching. It's heavier than bridge.py, so it fits a "production version" step rather than the core demo.

Robusta

open-source engine (Robusta Classic)
Background
step 08step 11

What it is: rule-based enrichment of Prometheus alerts with pod events, logs, graphs and related objects, via an Alertmanager webhook and YAML playbooks.

Borrow: attach the obvious context to the ticket before the agent starts, so the LLM skips its first few routine tool calls.

agent-sandbox

kubernetes-sigs · SIG Apps · v1alpha1
Upstream direction
step 12

What it is: a Sandbox resource and controller for isolated, stateful single-pod workloads, aimed at agent runtimes and untrusted LLM-generated code. Pause/resume support; stronger isolation through gVisor or Kata is a goal.

Borrow: a future home for the diagnosis Job. Today's Job and admission policy are simpler and enough, because the investigator runs no generated code.

Chaos Mesh

CNCF
More scenarios
step 13

What it is: faults declared as custom resources: PodChaos, NetworkChaos (latency, loss, partition), StressChaos, IOChaos, DNSChaos, HTTPChaos.

Borrow: failures no git commit can cause, which test the agent's escalate path (like scenario 06) rather than its PR path.

krkn · LitmusChaos

CNCF
Alternatives
step 13

krkn (Red Hat, CNCF Sandbox): pod, container, node and zone failures plus CPU, memory and I/O hogs, with a pass/fail signal and a resiliency score from Prometheus. LitmusChaos: a web UI (ChaosCenter) and an experiment catalog (ChaosHub).

Chaos Mesh is the lightest of the three on a single-node kind cluster.

Langfuse

self-hostable · accepts OpenTelemetry
Agent tracing
step 11step 12

What it is: open-source LLM tracing and evals. It records each diagnosis as a tree of model and tool calls with tokens, cost and latency, and takes standard OTLP spans.

Borrow: turn reasoning_steps and the timed tool log into real traces, and compare Haiku and Sonnet runs on the same scenario.

kubectl-ai

Google Cloud
Less relevant
interactive

An interactive assistant that turns a request into kubectl commands and runs them. It's built to act, writes included, which is the opposite of the read-only-eyes principle here.

Argo Rollouts

Argo project
Honest baseline
demo story

Progressive delivery that rolls back automatically on failed metric analysis. It would stop scenarios 01–03 with no ticket and no AI. Worth saying out loud in the demo: the agent earns its place on failures a rollback can't handle and on the "why did this happen" write-up. (From general knowledge, not from this search.)
